# 上线配置模板

## 0. 当前限制与资源预检

这是未来上线模板，不是当前部署状态。原服务器上的学习项目已撤下，保留原网站；不要在同一台小内存服务器重新启动完整教学栈。

未来应使用隔离的测试环境，先检查可用内存、磁盘、现有服务占用和数据库的实际需求。构建在本地完成；不要边承载网站边编译或压测。容器内存上限必须根据实际启动和运行占用测定，过低上限会触发 cgroup OOM，即使主机 CPU 使用率不高也可能反复重启。Swap 不能代替足够的内存或正确的容量规划。

当前完整栈含两个数据库、Redis、RabbitMQ 和 JVM，不能仅凭 CPU 不高就判定适合 2 GiB 服务器。上线前还必须补身份认证和访问控制；当前教学接口不适合直接开放公网。以下步骤仅在完成容量、安全与回滚检查的独立环境执行。

## 1. 环境变量

```bash
cp .env.example .env
```

把 `.env` 中的数据库、MongoDB、RabbitMQ 密码改成强密码。`.env` 只保存在服务器，不提交 Git，也不放进前端构建产物。

## 2. 启动生产基础服务

```bash
docker compose --env-file .env up -d --build
docker compose ps
```

公网只暴露 Nginx 的 80/443。MySQL、MongoDB、Redis 和 RabbitMQ 不应绑定公网地址；本地 Compass 调试端口在生产环境应移除。

## 3. 域名与 HTTPS

DNS 建议：

```text
status.example.com  -> 服务器公网 IP
api.example.com     -> 服务器公网 IP
```

先把 `infra/nginx/https.conf.example` 复制成服务器上的 Nginx 配置，替换真实域名和证书路径，再挂载证书目录：

```yaml
volumes:
  - ./infra/nginx/https.conf.example:/etc/nginx/conf.d/default.conf:ro
  - ./infra/nginx/certs:/etc/nginx/certs:ro
```

证书可以由腾讯云 EdgeOne、云厂商证书服务或 Let's Encrypt 提供。证书更新后执行 `nginx -t`，确认无误再 reload。

## 4. Flutter Web 发布

```bash
flutter build web --release --dart-define=API_BASE_URL=https://api.example.com
```

将 `build/web` 部署到静态站点或对象存储。移动端 APK/AAB 使用同一个 HTTPS API；iOS IPA 需要 macOS、Xcode 和 Apple 签名环境。

## 5. 正式上线前检查

- 修改所有默认密码。
- 删除 MongoDB 本地调试端口映射。
- 配置域名 DNS、HTTPS 和证书自动续期。
- 配置 SMTP、飞书 Webhook、COS/对象存储的 Secret。
- 配置服务器防火墙，只允许 22、80、443。
- 用 SSH Tunnel 访问内部管理端口，不直接开放数据库端口。
- 先执行健康检查和小流量压测，再切换 DNS。
