## 本轮实际通过的检查

- Python 日报离线自动测试：20 项通过；默认不外发、有凭据也不自动发送。
- Spring Boot：Maven 使用现有缓存离线测试，3 项通过；构建配置仍为 Java 8 字节码，本轮测试进程使用本机 JDK 17。
- Vue/Vite：防抖/节流与搜索的 8 项测试通过，构建通过；未新增第三方测试依赖。
- Flutter：使用现有 Pub 缓存、`flutter test --no-pub`，1 项 Widget 测试通过。
- 本机网关 `http://127.0.0.1:8088`：健康接口 200，API UP；日报实际读取状态、请求指标、缓存数据和 Docker 容器资源，未发送到外部。
- 故障实测：用本机不可用端口作为 API 目标，报告仍生成，四个接口分别记录失败，指标未知，Docker 采集继续执行。
- 浏览器交互实测：本地 `http://127.0.0.1:5200/` 的搜索从“等待输入完成”变成结果；两条临时目录数据搜索 `redis` 后只显示匹配的一条；返回顶部后按钮隐藏；未观察到浏览器错误日志。两条临时记录已核对标识并清理，未删除用户原有数据。
- 本机 Windows 使用现有 `docker-compose.exe config --quiet` 校验通过；原生 `docker.exe` 在当前配置下没有 Compose 子命令插件，不能把它的调用失败误认为配置错误。GitHub 工作流仍使用 Linux runner 的 `docker compose`。
- APK/Web/JAR：本轮核对既有产物存在，不表示本轮重新打包所有平台。
- 本轮没有下载安装额外开发工具或依赖。
